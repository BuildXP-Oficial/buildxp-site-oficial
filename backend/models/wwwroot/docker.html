01
O que é Docker?
Docker empacota sua aplicação e o que ela precisa para rodar dentro de um container, um ambiente isolado e repetível. Em outro computador ou servidor, o mesmo container tende a se comportar igual, o que ajuda muito em time e em produção.
Com Docker fica mais fácil rodar seu projeto sem precisar instalar no Windows Local cada coisa separada que o banco ou a stack pedem. Por exemplo, você quer PostgreSQL, SQL Server ou outro motor: em vez de montar tudo manualmente na máquina, você pode subir uma imagem pronta que já traz o serviço configurado e só expõe a porta que você precisa.
💡 Pensa no container como uma caixa fechada com um processo principal (ex.: servidor web ou base de dados).
02
Instalar o Docker
O Docker precisa estar instalado e rodando para os comandos docker ... e para os seus containers funcionarem. No Windows e macOS isso costuma ser o Docker Desktop (abra o app e espere ficar “running”). No Linux, o serviço do Docker precisa estar ativo.
Baixe o Docker Desktop no site oficial se você usa Windows ou macOS: engine, terminal docker e interface na mesma instalação.
# Windows / macOS: https://www.docker.com/products/docker-desktop # Linux (Ubuntu, exemplo) sudo apt update sudo apt install docker.io sudo systemctl start docker sudo systemctl enable docker # Conferir se o cliente responde docker --version docker run hello-world
03
Imagem e container
Uma imagem é o modelo, como uma receita fixa. Um container é uma instância rodando criada a partir dessa imagem. Você pode ter vários containers da mesma imagem, cada um com nome e portas diferentes.
Se você quer testar algo do Docker Hub, você puxa a imagem com docker pull. Para ver o que já baixou na máquina, use docker images.
ℹ️ Imagem é a receita. Container é o prato servido.
# Baixar uma imagem do Docker Hub docker pull nginx # Listar imagens locais docker images
04
Rodar seu primeiro container
O comando docker run usa uma imagem (baixa se ainda não existir) e cria e inicia um container. É o comando que você mais vai repetir.
--name dá um nome fácil para parar e ver logs. -p portaDoPc:portaNoContainer libera um serviço para o navegador ou para um cliente na sua máquina. -d roda em segundo plano. --rm apaga o container quando ele para, ótimo para testes rápidos.
# Teste oficial do Docker docker run --rm hello-world # Nginx em segundo plano na porta 8080 do seu PC docker run -d --name meu-nginx -p 8080:80 nginx # Abra no navegador: http://localhost:8080
💡 -d é “detached” (segundo plano). -p 8080:80 significa porta 8080 no seu computador apontando para a porta 80 dentro do container.
PAUSA
Até aqui você já viu o motor ligado, imagem, container e uma página web na porta. Respira um pouco antes de subir banco de dados de verdade.
💡 Se algo falhar, anote a mensagem vermelha no terminal ou use docker logs nomeDoContainer depois que você souber o nome.
05
Só o banco no Docker (cenário comum)
Muita gente usa Docker para rodar só PostgreSQL ou MySQL no desenvolvimento, sem instalar o servidor completo no Windows Local. O container sobe rápido e você mata quando não precisa mais.
No exemplo abaixo você define senha com variável de ambiente e publica a porta padrão do Postgres no seu localhost. Os dados somem se você apagar o container sem volume, o que pode ser ok para aprender. Para projeto sério, depois você aprende volume no Compose.
# Uma linha (PowerShell, bash ou CMD) docker run -d --name meu-pg -e POSTGRES_PASSWORD=minhasenha -p 5432:5432 postgres:15
06
Banco de dados dentro do container
Aqui o objetivo é rodar SQL contra o Postgres que já está no container. Você não precisa instalar o cliente no Windows se não quiser: você entra no container e usa o psql que já veio na imagem.
docker exec -it nomeDoContainer bash abre um shell interativo dentro do container em execução. De lá você chama psql com usuário postgres e a senha que você passou em POSTGRES_PASSWORD.
docker exec -it meu-pg bash psql -U postgres -d postgres CREATE DATABASE teste; \c teste CREATE TABLE msg (id SERIAL PRIMARY KEY, texto TEXT); INSERT INTO msg (texto) VALUES ('Olá Docker'); SELECT * FROM msg; \q exit
Se der erro, confira nesta ordem: o Docker Desktop ou serviço Linux está rodando? A porta 5432 no seu PC está livre ou já tem outro Postgres? O nome do container (meu-pg) é o mesmo do docker run? Rode docker logs meu-pg e leia a última mensagem. Usuário e senha batem com o que você passou em -e?
07
Cliente SQL no seu computador
Se você prefere DBeaver, pgAdmin, extensão do VS Code ou outra ferramenta, desde que você tenha usado -p 5432:5432, você aponta para host localhost, porta 5432, usuário postgres e a senha que você definiu em POSTGRES_PASSWORD.
💡 A linguagem dentro do servidor continua sendo SQL; muda um pouco o dialeto entre Postgres, MySQL e SQL Server, mas o fluxo “subir container, abrir porta, conectar” é o mesmo.
08
MySQL em container (mesma ideia)
Se você quer MySQL ou MariaDB, a ideia é igual: imagem oficial, variável de ambiente para senha do root, porta publicada. O cliente dentro da imagem costuma ser mysql.
docker run -d --name meu-mysql -e MYSQL_ROOT_PASSWORD=rootpass -p 3306:3306 mysql:8 docker exec -it meu-mysql mysql -uroot -prootpass -e "SHOW DATABASES;"
09
Listar, parar, logs e remover
docker ps mostra o que está ligado. docker logs ajuda quando o container não sobe ou o banco recusa senha. docker stop desliga. docker rm remove o container parado e libera o nome para usar de novo.
docker ps docker ps -a docker logs meu-nginx docker stop meu-nginx docker rm meu-nginx
10
Dockerfile da sua aplicação
Quando você quer empacotar sua API ou site e não só usar uma imagem pronta, você escreve um arquivo chamado Dockerfile na pasta do projeto. Ali você diz a imagem base, dependências, porta e o comando que inicia o processo.
# Dockerfile (exemplo Node) FROM node:20-alpine WORKDIR /app COPY package*.json ./ RUN npm install COPY . . EXPOSE 3000 CMD ["node", "index.js"]
docker build -t minha-api . docker run -d -p 3000:3000 --name api minha-api
11
Docker Compose (vários serviços)
Quando você quer subir api + banco + cache sempre juntos, um arquivo compose.yml descreve cada serviço. Um comando sobe tudo, outro derruba.
# Exemplo resumido compose.yml services: app: build: . ports: - "3000:3000" depends_on: - db db: image: postgres:15 environment: POSTGRES_PASSWORD: senha123 volumes: - pgdata:/var/lib/postgresql/data volumes: pgdata:
docker compose up -d docker compose down
PAUSA
Você já cobriu web na porta, Postgres e MySQL em container, cliente SQL, rotina de logs e Compose. O próximo passo é usar isso no seu projeto real.
FIM
Base Docker para o dia a dia
Agora você sabe subir serviços isolados, conectar ao SQL e organizar app com banco usando Compose. Volte sempre à referência rápida ou ao terminal BuildXP para fixar comando.
