VERSION CONTROL
Git & GitHub
LVL 8 · ESSENTIAL
2400 XP
01
O que é Git?
Git é um sistema de controle de versão — rastreia todas as mudanças no seu código ao longo do tempo. Pensa nele como um histórico infinito com "save points" que você cria. GitHub é a plataforma online onde você hospeda esse histórico e colabora com outras pessoas.
💡 Git ≠ GitHub. Git roda na sua máquina. GitHub é onde você guarda e compartilha.
02
Instalar o Git
Baixe e instale o Git de acordo com seu sistema operacional.
# Windows → https://git-scm.com/download/win # macOS brew install git # Linux (Debian/Ubuntu) sudo apt install git # Verificar instalação git --version
03
Configurar sua identidade
Antes de qualquer coisa, diga ao Git quem você é. Esses dados aparecem em cada commit seu.
git config --global user.name "Seu Nome" git config --global user.email "seu@email.com"
ℹ️ Use o mesmo e-mail da sua conta GitHub para os commits aparecerem no seu perfil.
04
Inicializar seu primeiro repositório
Entre na pasta do seu projeto e inicialize o Git.
cd meu-projeto git init
💡 Isso cria uma pasta oculta .git — ela contém todo o histórico. Nunca a delete.
05
Seu primeiro commit — o ciclo básico
O fluxo do Git tem 3 estágios: Working Directory → Stage → Commit. Você escreve (working), seleciona o que vai salvar (stage), e salva definitivamente (commit).
git status # ver estado atual git add . # stage de tudo git commit -m "feat: meu primeiro commit"
⚠️ Mensagens de commit importam. Use verbos no imperativo: feat, fix, update, remove, docs.
06
Conectar ao GitHub e enviar
Crie um repositório no GitHub (botão "New Repository"), depois conecte e envie.
git remote add origin https://github.com/usuario/repo.git git push -u origin main
ℹ️ O -u define o upstream — nos próximos pushes basta git push.
07
Branches — trabalhando em paralelo
Branches permitem desenvolver features sem afetar o código principal. É a base do trabalho em equipe.
git checkout -b minha-feature # criar e entrar na branch git branch # listar branches git checkout main # voltar pra main git merge minha-feature # juntar à main
08
Puxar atualizações do remoto
Quando outras pessoas commitem, você precisa atualizar sua cópia local.
git pull # puxar e mergear git fetch # só verificar sem aplicar
💡 Faça git pull sempre antes de começar a trabalhar para evitar conflitos.

SETUP & CONFIG
git --versionVer versão do Git instalada
git config --global user.name "Nome"Definir nome do usuário
git config --global user.email "email"Definir e-mail do usuário
git config --listListar todas as configurações
REPOSITÓRIO
git initInicializar repositório na pasta atual
git clone <url>Clonar repositório remoto
git remote -vListar repositórios remotos
git remote add origin <url>Conectar ao repositório remoto
STAGE & COMMIT
git statusVer estado dos arquivos
git add .Stage de todos os arquivos modificados
git add <arquivo>Stage de arquivo específico
git commit -m "msg"Commitar com mensagem
git commit --amendEditar o último commit
git log --onelineHistórico resumido de commits
git diffVer mudanças não staged
BRANCHES
git branchListar branches locais
git checkout -b <nome>Criar e entrar na branch
git switch <nome>Trocar de branch (Git moderno)
git merge <branch>Mergear branch na atual
git rebase <branch>Rebasear commits
git branch -d <nome>Deletar branch local
PUSH & PULL
git pushEnviar commits ao remoto
git push -u origin <branch>Push inicial com upstream
git pullPuxar e mergear mudanças
git fetchPuxar sem mergear
git push origin --delete <branch>Deletar branch remota
DESFAZER & EMERGÊNCIA
git restore <arquivo>Descartar mudanças não commitadas
git restore --staged <arquivo>Remover do stage
git reset --soft HEAD~1Desfazer último commit (mantém mudanças)
git reset --hard HEAD~1Desfazer e APAGAR mudanças ⚠️
git stashSalvar mudanças temporariamente
git stash popRestaurar do stash
git revert <hash>Reverter commit sem apagar histórico
